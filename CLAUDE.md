## Project Overview

**RocketDB** is a real-time rocket launch tracker deployed as a static site on GitHub Pages at `https://nks648.github.io/RocketDB/`.

- **Stack**: React 18 + Vite 5, no backend, no database
- **Deployment**: GitHub Actions → `gh-pages` branch → GitHub Pages
- **Base path**: `/RocketDB/` (configured in `vite.config.js`)
- **Branch**: All development happens on `claude/rocket-launch-dashboard-8cJtz`

## Data Sources

### Primary — The Space Devs LL2 API
```
https://ll.thespacedevs.com/2.2.0   ← PRODUCTION (always use this)
```
- **Never use** `lldev.thespacedevs.com` — it lags on data updates
- Rate limit: **15 req/hr** (free tier)
- Cache TTL: **10 min** (`rocketdb:ll2:v3:` prefix in localStorage)
- Endpoints:
  - `GET /launch/upcoming/?format=json&limit=50&mode=detailed`
  - `GET /launch/previous/?format=json&limit=30&ordering=-net&mode=detailed`
- Force-refresh: the 🔄 button calls `clearCache()` then force-fetches — bypasses TTL

### Supplementary — RocketLaunch.Live
```
https://fdo.rocketlaunch.live/json/launches/next/25
```
- Free, no API key, CORS-enabled
- Used for date hints when LL2 has TBD/TBC status
- Cache TTL: 10 min (`rocketdb:rll:v1`)
- Matching: `matchRLL(ll2Launch, rllLaunches)` — score ≥ 2 by rocket+provider name

### Supplementary — Scraped Intel JSON
```
https://nks648.github.io/RocketDB/launch-intel.json
```
- Generated by `scripts/scrape-intel.js` every 6 hours via GitHub Actions
- Sources: SpaceFlightNow, Wikipedia, SpaceX API
- Cache TTL: 6 h (`rocketdb:intel:v1`)
- Matching: `matchIntel(ll2Launch, intelLaunches)` — score ≥ 2

### Images — Fallback Chain
`useRocketImage(launch)` resolves in order:
1. `launch.image` (LL2 launch photo)
2. `launch.rocket.configuration.image_url` (LL2 rocket config)
3. Wikipedia action API via `rocket.configuration.wiki_url`
4. Wikipedia keyword search (`"{rocketName} rocket launch vehicle"`)
5. Agency logo (`launch_service_provider.image_url`)

In-memory cache keyed by `launch.id`.

### Other APIs (all CORS-friendly, no key needed)
| API | Used for |
|-----|----------|
| Open-Meteo (`api.open-meteo.com`) | Pad weather |
| NOAA SWPC (`services.swpc.noaa.gov`) | Space weather |
| Wikipedia REST + Action API | Rocket images, orbital launch data |
| Reddit search API | Discussion threads |
| SpaceX community API (`api.spacexdata.com/v4`) | Scraper only |

## Launch Status IDs (LL2)

| ID | Key | Meaning |
|----|-----|---------|
| 1 | `go` | Go for Launch |
| 2 | `tbd` | TBD — placeholder date |
| 3 | `success` | Launch Successful |
| 4 | `failure` | Launch Failure |
| 5 | `hold` | On Hold |
| 6 | `partial` | Partial Failure |
| 7 | `abort` | In-Flight Abort |
| 8 | `tbc` | TBC — rough date |

Statuses `[2, 5, 8]` are "scrubbed/hold" — kept in Upcoming even if past NET.
Statuses `[3, 4, 7]` are "final" — shown in Previous.

## Date Intelligence System

When LL2 has TBD/TBC dates, three supplementary hints appear in the detail panel:

### 📡 RocketLaunch.Live hint (cyan)
- Shows when `matchRLL()` finds a match with `win_open` or `date_str`
- "Unconfirmed — not in LL2 API yet"

### 🗞 Intel hint (purple)
- Shows when `matchIntel()` finds a match in `launch-intel.json`
- Source label: SpaceFlightNow / Wikipedia / SpaceX API
- Confidence: `high` (has specific time) or `low` (date only)

### 📌 User pin (yellow)
- User manually enters date + optional note (e.g. from company announcement)
- Stored in `localStorage` under `rocketdb:date-overrides:v1`
- Prefilled from RLL or Intel date when editing
- Shown on both desktop (`LaunchDetail`) and mobile (`MobileLaunchBanner`)

Priority display order: **user pin → RLL → Intel** (only one shown at a time, except pin always shows edit button)

Tablet breakpoints:

- `≤ 1024px` → sidebar 270px
- `≤ 900px` → sidebar 230px, hide stats agencies/chart

### Mobile (≤ 768px)
- Sidebar becomes a **bottom sheet** (pull-up handle)
- Selected launch shows as a **floating banner** at the bottom with expand (ℹ) button
- `MobileLaunchBanner` contains: weather, all detail rows, date hints, orbital params, streams

### Key z-index values
| Element | z-index |
|---------|---------|
| Header | 1200 |
| Map markers | 400 |
| LaunchDetail | 900 |
| Shortcut panel backdrop | 2999 |
| Shortcut panel | 3000 |
| VideoModal | 9000 |
| CinematicMode | 10000 |

**Critical**: `.header` must use `position: relative` to avoid creating a stacking context that traps `position: fixed` children below other content.

## Scraper (`scripts/scrape-intel.js`)

Node.js ESM script. Runs in GitHub Actions with internet access.

**Sources:**
1. **SpaceFlightNow** (`spaceflightnow.com/launch-schedule/`) — HTML scrape
   - 3 strategies: `.datename` CSS → `<strong>` date tags → table rows
   - Logs first 600 chars of HTML + all class names for debugging
2. **Wikipedia** (`List_of_orbital_launches_of_YEAR`) — Wikipedia API → HTML tables
   - Auto-detects columns by header text (date/rocket/payload/site/operator)
   - Falls back to `YEAR-1` if current year article is empty
3. **SpaceX API** (`api.spacexdata.com/v4/launches/upcoming`) — reliable JSON, no scraping

**Output**: `public/launch-intel.json`
```json
{
  "updated": "2026-04-09T17:32:20.604Z",
  "sources": ["SpaceFlightNow", "Wikipedia", "SpaceX API"],
  "launches": [
    {
      "rocket": "Falcon 9",
      "mission": "Starlink Group 17-35",
      "provider": "SpaceX",
      "site": "...",
      "net": "2026-04-10T00:00:00.000Z",
      "window": "hour",
      "source": "SpaceX API",
      "sourceUrl": "...",
      "confidence": "high"
    }
  ]
}
```

To run manually: `node scripts/scrape-intel.js`
To trigger via GitHub: Actions tab → "Scrape Launch Intel" → Run workflow

## localStorage Keys

| Key | Content | TTL |
|-----|---------|-----|
| `rocketdb:ll2:v3:{url}` | LL2 API responses | 10 min |
| `rocketdb:rll:v1` | RLL launches array | 10 min |
| `rocketdb:intel:v1` | launch-intel.json array | 6 h |
| `rocketdb:date-overrides:v1` | `{ [launchId]: { net, note, savedAt } }` | permanent |
| `rocketdb:favs:v1` | Set of favourite launch IDs | permanent |
| `rocketdb:theme` | `"dark"` or `"light"` | permanent |

**Cache key versioning**: bump the version suffix (e.g. `v2` → `v3`) in the hook to force all users' browsers to drop stale data on next load.

## Common Gotchas

1. **Never use `lldev.thespacedevs.com`** — it lags on data updates. Always use `ll.thespacedevs.com`.

2. **Stacking contexts**: Adding `z-index` to a grid/flex item creates a stacking context that traps `position: fixed` children. The Header must keep `position: relative; z-index: 1200`.

3. **React hooks before early returns**: `useRocketImage` and any other hooks must be called before `if (!launch) return null`.

4. **Cache invalidation pattern**: bump `LS_PREFIX` version string in `useLaunches.js` whenever switching data sources or fixing data shape bugs.

5. **Mobile Safari**: `position: fixed` inside a transformed parent breaks. All fixed overlays must be siblings of (not children of) transformed elements.

6. **Vite proxy vs GitHub Pages**: The `vite.config.js` proxy only works in dev — in production (GitHub Pages), any server-side proxy approach fails. All data fetches must be direct CORS-compatible API calls.

7. **LL2 rate limit (15 req/hr)**: With 2 endpoints per fetch, max 7 fetches/hr. 10-min TTL = 6 fetches/hr ✓. Do not reduce TTL below 8 minutes.
